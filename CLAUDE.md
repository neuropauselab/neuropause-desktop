## 2 · NON-NEGOTIABLES

1. **Frozen surfaces change only through an FG gate.** Protocol (proven in FG-1, now law): write the gate doc → present the **verbatim** diff + threat analysis both directions + verification plan → run the human's read-only confirmations → wait for the literal token (`AUTHORIZED: FG-N — <subject>, per gate doc`) → apply via the change-control choreography. Silence is not consent; enthusiasm is not consent; only the token is consent. A diff that changes after the token requires a new token.
2. **Change-control choreography (proven, mandatory for every frozen touch):** clean checkpoint → `certification/freeze-baseline.sh` re-record → `verify-freeze.sh` INTACT (#1, committed) → apply the authorized diff + minimum accompaniment → full suites green → one isolated commit → re-record → INTACT (#2, committed) → evidence doc recording the frozen/non-frozen path split, both INTACT baselines, and the token quoted verbatim.
3. **Micro-authorization rule:** if authorized scope proves insufficient mid-flight (one line becomes two, a third guard fires), REVERT to the last clean state and ask. Never silently exceed scope; never leave a red tree; never re-record a baseline against red. **COROLLARY (operator, 21 Aug 2026): WHEN A DEFECT IS IN A SHARED PARAMETER, THE UNIT OF CORRECTION IS THE PARAMETER'S CALLERS, NOT THE LINE NAMED.** Fixing one caller of a shared function leaves the parameter carrying a different meaning per caller — **an inconsistent contract, which is a worse defect than the one being repaired.** So the accompaniment is *mandatory*, not permitted, and the obligation is to **disclose it loudly rather than to stop**: the rule forbids exceeding scope *silently*, not exceeding it. Worked example: F-P45's counter fix named `unified/sync/index.ts:191`, and `withWriteStates` had two callers — correcting only the named one would have made the panel read `0` on first load and real counts on the next sync event.
4. **Never fake green.** No weakened assertions, skipped tests, widened timeouts, or mocks standing in for a thing the slice says to make real. A true FAIL outranks a false PASS. A permanently red verifier is as corrosive as a fake green — fix the cause or gate it, never normalize it.
5. **Evidence or it didn't happen.** Every slice ships `certification/source-update/PHASE-I-A3-NEUROPAUSE-OS-WAVE-<W>-SLICE-<N>-…-EVIDENCE.md` with honest labels — `SOURCE-PROVEN` / `TEST-VERIFIED` / `LIVE-VERIFIED` / `PILOT-VALIDATED` — never stronger than the evidence beneath.
6. **AI output is untrusted data, everywhere, forever.** External content ≠ instruction authority. The AI never sets identity, tenant, account, approval, `confirmed`, or policy. It produces candidates for validated, fail-closed paths only.
7. **One confirmation architecture.** Everything consequential flows proposal → human review → confirm → CST → admission → execution → outcome → evidence. Building a second path is a defect.
8. **Deny-by-default.** Unknown capability, recipient, account, tenant, connector, parameter, policy, or verification state → DENY, fail closed.
9. **Uncertainty is never success.** UNKNOWN → HOLD → RECONCILIATION → VERIFIED_SUCCESS / VERIFIED_FAILURE / UNRESOLVED. UNRESOLVED remains unresolved.
10. **Offline ≠ execution authority** unless an explicitly certified offline policy says otherwise.
11. **Governance boundary honesty:** anything outside proven coverage is explicitly marked NOT GOVERNED — never silently treated as governed.
12. **Secrets:** never invented, hardcoded, or committed. `.env.example` documents; real values arrive only at human gates.
13. **The Brain proposes; it never reaches.** Live Brain (L6) is never granted LLM→shell, LLM→API, LLM→connector, or LLM→database. Its ONLY path to any external effect is **BRAIN → PROPOSAL → GOVERNANCE → NEUROPAUSE EXECUTION → EXTERNAL EFFECT → INDEPENDENT VERIFICATION → ACTION RECORD.** Its state model and reasoning hold ZERO execution or grant authority (zero-runtime-import into governance/execution, pinned). Model output inside the Brain is untrusted data (§6) and sets no identity, tenant, account, approval, or policy. Approved with L6-S1 (operator, 19 Aug 2026).

A 2xx / ack / executor return is *submission*, not verification. Where no independent oracle exists the effect is honestly **UNVERIFIABLE** (stated, never silently VERIFIED). **Send-corroboration is never delivery.** Canonized with the S4 opening (operator, 19 Aug 2026).
15. **Memory informs governance; memory never becomes governance.** A prior verified success is EVIDENCE for a proposal — never permission. The system must never learn "last time this worked, therefore I am allowed": no outcome memory, experience record, or reproduction fingerprint ever sets authority, approval, `confirmed`, policy, or admission; every consequential action re-derives authorization from the live substrate at execution time, regardless of history. Similarity to a past success NEVER auto-converts to certainty or permission. Canonized with the Phase-0 acceptance (operator, 19 Aug 2026).

17. **Claims are pinned against the real production path.** Verbatim (operator, 20 Aug 2026): *"A certification or architectural claim about a runtime property must be pinned against the real production path whenever that path is available. A hand-built fixture may test behavior, but it cannot establish that the production runtime supplies the same substrate."* Short form: **pin against the real path, not a convenient shape.** Canonized from F-N19-2, where a fixture carrying `outcome.requestId` — a field the real `TransitionOutcome` does not have — let a green suite hide the fact that `requestId` is `''` and `requestTime` structurally null in production. A fixture more generous than reality is a false green with extra steps. Corollary: **"timeline key exists ≠ real timestamp was measured"** — the presence of a field is not evidence that the value it holds was ever observed.

18. **A data-model change that alters what the system is permitted to do is a GOVERNANCE change.** Verbatim (operator, 20 Aug 2026): *"A data-model change that alters what the system is permitted to do is a governance change — it requires its own explicit ruling and gate. Specifically: a temporal attribute must never silently weaken an existing governance decision."* **The operational test, verbatim:** EXISTING GOVERNANCE + NEW FIELD → does the field change the decision? → YES → new governance semantics → explicit ruling + presented gate. **Data-model changes can be policy changes.** Canonized from NP-017, where `valid_to` on a typed link would have been a lapsing refusal: the one enforcement that consumes links consumes their EXISTENCE, so *an expiring link is a lapsing refusal* and *a weak link refuses exactly as hard as a strong one*. Corollary recorded with F-N17-4: **"A declared governance capability is not the same thing as a reachable governance path."**

19. **Every consequential governance decision must have TRUTHFUL DURABLE GOVERNANCE EVIDENCE, while EXECUTION and VERIFICATION remain SEPARATE EVIDENCE CLASSES.** Verbatim (operator, 21 Aug 2026), and it **replaces "add an emitter everywhere," which was never the requirement.** **OBSERVABLE IS NOT RECORDED:** the log is *diagnostic*; the **evidence store is the record**. F-P24's requirement therefore names its artifact — **the ActionRecord, not `app.log`.** Worked example: the FG-10 gate's REFUSE emits at `warn` and mints nothing, so *an ActionRecord audit sees a ceremony that never refused*. The three classes must not collapse into one another — a governance DENY is `governance=DENY, execution=NOT_STARTED, verification=NOT_APPLICABLE`, and **must never be converted into `execution_failed`**; the VERIFICATION class is reconciled against D-16's `verificationTerminals.ts` and NP-018's `Certainty` (including `STALE`), never minted alongside. Corollary from F-P39: **a verification class with no production caller is not a separate evidence class — it is an absent one.**

20. **Where a governing document and established source disagree about a fact of the code, THE SOURCE WINS AND THE DOCUMENT IS CORRECTED.** Verbatim (operator, 21 Aug 2026). A document does not get the benefit of the doubt for being the constitution: §1 is a *record* of what the code does, and a record that contradicts the code is a defect in the record. **The correction is mandatory and immediate — not a follow-up item**, because a stale §1 is read at every session start and therefore misinforms every subsequent decision until fixed. Corollary, from the case that canonized it: **two lines of the same document contradicting each other is not a tie to be adjudicated on style or recency — go to the source and correct the one that is wrong.** Canonized from ruling A on F-P39, where `:25` claimed "the S22 reconciler is its production caller" while `:30` said "S22 reconciler missing"; the import graph settled it, `:30` was correct, and `:25` was corrected. Sibling of #17 (*pin against the real path*): #17 governs TESTS that describe the code, #20 governs DOCUMENTS that describe the code. **DOCUMENTING A DEFECT DOES NOT FIX IT** — a defect faithfully described in a document is still open, and only a VERIFIED correction closes it.

21. **A FINDING'S STATEMENT EXPIRES WHEN WORK LANDS AGAINST IT. RE-MEASURE, OR THE REGISTER BECOMES A HISTORY OF WHAT USED TO BE WRONG.** Verbatim (operator, 21 Aug 2026). A finding is a *measurement with a date*, not a permanent property of the system. The moment a slice lands against one, its statement is a claim about a codebase that no longer exists — and an OPEN row nobody re-measured is indistinguishable, at a glance, from an OPEN row that is still true. **The status may survive re-measurement while the STATEMENT does not**, and that is the dangerous case: the row still says OPEN, so nothing looks wrong, while the *reason* it is open has silently moved to a different layer. Sibling of #17 (*pin against the real path*) and #20 (*source wins over document*): **#17 governs tests, #20 governs documents, #21 governs FINDINGS — the documents most likely to be read as current precisely because they are filed as open.**

22. **EVERY CLAIM CARRIES ITS ORIGIN: CURRENT SOURCE · PRIOR REPORT · CONVERSATIONAL CLAIM · INFERENCE · NOT_ESTABLISHED.** Adopted as standing method (operator, 21 Aug 2026), carried forward from a superseded directive's §28 so it survives as practice rather than as a one-off. **A PRIOR REPORT IS AN ENTERING FINDING AND CANNOT STRENGTHEN ITSELF** — re-stating a measurement does not re-measure it, and a claim that has been repeated three times is exactly as strong as the one reading underneath it. The tags are not decoration: they are what makes #20 and #21 enforceable, because a document cannot be checked against source unless it says which of its sentences ever came from source. **A CONVERSATIONAL CLAIM IS THE MOST DANGEROUS CLASS** — it arrives with the authority of the person who said it and no file behind it, which is how a governance apparatus gets conjured in dialogue and then cited as though it constrains. Worked example, F-P24's re-measurement: the operator's claim *"the CST verdict IS recorded on all branches"* was verified and promoted to CURRENT SOURCE **with a refinement it did not contain** — it holds only for branches that REACH the observer, and the L6 refusal returns before it.

23. **THREE FAILURES THAT LOOK ALIKE AND ARE NOT: NOT REACHABLE ≠ REACHABLE BUT NEVER EXECUTED ≠ EXECUTED BUT THE MEASUREMENT CANNOT READ ITS RECORD.** Adopted as standing method (operator, 21 Aug 2026). All three present as *"the feature does not work"* and all three have **completely different remedies** — wire it, run it, or fix the reader — so collapsing them sends the fix to the wrong layer. F-P39/F-P41 are the worked example and were misdiagnosed in exactly this way: the register said the terminal was absent (failure 2) when the binding defect was an org-keyed query (failure 3), and **producing terminals alone would not have moved the counter.** Pairs with §5.0d's ladder, where the same distinction is the gap between REACHABLE and BELIEVABLE. **COROLLARY: an assertion that is UNSATISFIABLE BY CONSTRUCTION is a different object from one that merely fails.** A failing assertion reports a wrong value; an unsatisfiable one reports nothing at all, because no execution could ever have satisfied it — it is a test-shaped hole, and it passes silently the moment someone writes it as an equality against another zero.

24. **A RED IS A MEASUREMENT, AND MEASUREMENTS HAVE INVOCATIONS — VERIFY THE INVOCATION BEFORE BELIEVING THE RESULT.** Twelfth instrument instance (operator, 21 Aug 2026), self-caught. Worked example: a full-suite run reported **179 failed files**, and the failures were real output from a real runner — but the runner had been invoked from the repository root instead of `apps/desktop`, so `vitest.setup.ts` never loaded and unrelated modules reported *"no organization and workspace are active."* **A red obtained from the wrong invocation is not evidence of a defect; it is evidence about the invocation.** The rule cuts both ways and the green direction is the more dangerous one — #2 #4's *never fake green* is usually read as "don't weaken assertions", but **a green from the wrong scope is a fake green nobody had to author.** Corollary, from the same class: `| head -N` on a command whose absence you intend to claim is an instrument that manufactures absence.

25. **RULINGS ARE THE FOURTH EXPIRING CLASS — AND THE MOST DANGEROUS OF THE FOUR.** Verbatim (operator, 21 Aug 2026): *rulings expire when work lands against their premise.* Tests expire (#17), documents expire (#20), findings expire (#21), **and rulings expire — but rulings are treated as SETTLED BY CONSTRUCTION, because they were DECIDED rather than MEASURED.** Nothing about a ruling invites re-measurement: it carries the authority of the person who made it, it is filed as closed, and its premise is usually implicit rather than written down. **A ruling therefore outlives its premise silently, and by default nobody is looking.** Worked example, recorded by the operator against their own rulings: **R2** (*"subject cannot be a limb"*) and **R5 condition 1** (*"uniqueness keyed on recipient within the interval"*) were both correct when made and both expired the moment D2 aligned the fingerprint codomains — R2 into a proposal that would DELETE a working limb, R5-1 into a specification for a two-limb world that no longer exists. **Both expired on the same day, silently, and were caught by the worker rather than by the author.** The defence is that a ruling states its premise explicitly, so that the premise can be re-measured without re-litigating the decision.

26. **A LAW MAY TIGHTEN UNDER LANDED WORK. THE WORK IS NOT THEREBY WRONG — IT IS THEREBY SUPERSEDED.** Verbatim (operator, 21 Aug 2026). **Record WHICH FORMULATION the slice met**, so the corpus shows a slice that cleared the bar in force at the time rather than a slice that failed the bar written later. Worked example: **P4-MIN met F-P24's formulation as it then stood — *a refusal must be observable* — and §2 #19 subsequently redefined the artifact as the evidence store rather than the log.** **THE PROTECTION EXISTS FOR A REASON, AND THE REASON IS INCENTIVES: IF TIGHTENING A LAW RETROACTIVELY INDICTS PAST WORK, THE INCENTIVE IS NEVER TO TIGHTEN.** A programme that punishes its own ratchet stops ratcheting, and the laws freeze at whatever strength they had on the day someone first complied. So the register records supersession, never fault — and the tightening stays cheap to make.

27. **A CONTRACT PIN MUST DERIVE ITS EXPECTATION FROM THE CONSUMER, NEVER FROM THE PRODUCER.** Adopted as standing law (operator, 21 Aug 2026, from FG-15). **A pin that reads the producer asserts only that the producer equals itself** — it goes green on every value the producer can emit, including the wrong one, and it is indistinguishable from a real pin until the day it is needed. The requirement must flow **consumer → producer**, because that is the only direction in which a change to what is NEEDED can falsify what is SUPPLIED. Worked example: FG-15's query-shape pin parses `SentItem`/`InboxItem` out of `verifyEffect.ts` — the consumer's own source — and asserts the adapter's `$select` covers them; add a field to `SentItem` and the pin goes red until the adapter requests it. Sibling of #17: **#17 says pin against the real path; #27 says pin from the right END of it.** Corollary — a test that describes itself as a *"faithful mirror"* of the code under test is this defect wearing a compliment (F-P49).

28. **THE OPERATOR NEVER ASSIGNS AN F-NUMBER — AND NEVER CITES ONE FROM MEMORY. DESCRIBE THE FINDING; THE REGISTER RESOLVES THE NUMBER.** The first half was standing practice (it produced the ninth naming collision when a directive labelled its rulings `D1…D5` against a `DECISIONS.md` already holding `D-1…D-16`, and again when a directive assigned `F-P42`, which was taken). **The second half is the one that had never been written down, and it is the more dangerous:** assigning a number risks a collision, which is loud and gets caught — **citing one risks a phantom, which is silent and gets inherited.** Worked example (operator, 21 Aug 2026): a ruling assigned a real boundary — the propose refusal's operator-visibility half — to **`F-P22`, which does not exist anywhere in the corpus** (0 files; `F-P18` and `F-P20` are likewise absent). **The boundary was real; only its address was invented.** That is the trap: a citation to a non-existent finding looks like continuity, and **creating `F-P22` to make the reference resolve would have given the register a member whose only provenance was the citation itself** — §5.0e's conjured register acquiring a member through the front door. **The correct response to an unresolvable citation is to record the boundary, mark the identifier `NOT_ESTABLISHED`, and file at the next free number — never to manufacture the referent.** Sibling of §2 #22: an identifier is a claim like any other, and it carries an origin.

29. **A BEST-EFFORT WRITER THAT SWALLOWS ITS OWN FAILURES CANNOT TELL YOU WHETHER IT WROTE — SO THE CALLER MUST OBSERVE THE STORE, NEVER THE PROMISE.** Canonized from F-P52 (operator, 21 Aug 2026). A best-effort observer is *correct* to catch its own errors — §2 #19's evidence emitters must never block or alter the action they record. **But the same catch that protects the send destroys the signal that the write happened**: `await observe(...)` resolves identically whether a row was persisted or silently lost, so resolution proves only that the call finished. **THE REMEDY IS NOT TO MAKE IT THROW — that would put an evidence failure on the critical path and break the send, which is the thing the design correctly refuses.** The remedy is that **anything asserting a write occurred must READ THE STORE BACK.** **WORKED EXAMPLE — the debugging sequence that canonized it, because the shape of the confusion is the lesson:** a pin read zero rows; the store worked in isolation; the gate emitted with correct arguments; the emit *resolved cleanly* — and every one of those observations was true while a row was being dropped on every run. Four green signals and an empty store. Only reading the store back located the loader race. **THIS IS F-P24's SHAPE ONE LEVEL DOWN: there, governance refused and recorded nothing; here, THE SAFETY MECHANISM DESTROYS THE EVIDENCE OF ITS OWN OPERATION.** Sibling of §2 #17 and #27 — #17 says pin against the real path, #27 says pin from the consumer end, **#29 says pin on the durable artifact rather than on the call that was supposed to produce it.**

30. **A COMPLETE SEARCH OF THE WRONG SPACE IS INDISTINGUISHABLE FROM A COMPLETE ANSWER — THE SEARCH SPACE IS PART OF THE CLAIM.** Thirteenth instrument instance (operator, 21 Aug 2026), self-caught. Worked example: asking *"can a non-renderer path reach the governed send?"*, finding `registerSecureHandlers` binding via `ipcMain.handle`, and concluding **renderer-only**. **Tool right, execution right, result right, universe wrong** — `runSecureHandler` has four main-side callers and `handlerByChannel` is built explicitly *"so it can resolve any of them by channel"*, so the true answer needed three dispatchers enumerated, not one binding read. **DISTINGUISH IT FROM ITS FAMILY, because the remedies differ:** it is not a **wrong path** (`cd` drift — the target was right), not a **broken sweep** (the grep worked), not a **truncation** (`| head -N` hid nothing), not a **composed value** (`join(__dirname,…)` evading a literal match), not a **stale cwd**, and not a **wrong invocation** (#24 — the runner was correct). **Every one of those makes the instrument misreport; this one makes the instrument report perfectly about the wrong universe.** It is the hardest of the family to catch, because nothing looks wrong: no error, no empty result, no anomaly — a clean answer to a question narrower than the one asked. **THE REMEDY IS TO STATE THE SEARCH SPACE ALONGSIDE THE FINDING** (*"across these N call sites"*, *"over these three dispatchers"*), because a scope written down can be challenged and a scope held in the head cannot. Sibling of §2 #22: the search space is an origin claim about a negative.

31. **INCIDENTAL PROTECTION IS NOT A CONTROL.** Verbatim (operator, 21 Aug 2026). **A property that holds because two unrelated facts happen to align is UNTESTED, not safe** — nothing asserts it, nothing fails when it stops being true, and no one is told when one of the two facts changes. Worked example, F-P54: F-P48's identity check *would* refuse the confused-deputy case where a non-renderer dispatcher reached the governed send — **but only by coincidence**, because such a caller happens to carry no active workspace and the check happens to test workspace resolution. **Neither fact is about the other.** The protection is real today and would vanish silently the moment a dispatcher ran under a resolved principal. **THE TEST: can you name the mechanism that enforces it, and the assertion that fails when it breaks?** If the answer is *"it works out that way"*, it is a coincidence with good manners. **Record it as a finding, never as a mitigation** — because a mitigation is something the programme can rely on, and this is precisely something it cannot. Sibling of §2 #18 (*data-model changes can be policy changes*) and of *a local accommodation is a finding that was not filed*: all three are about protection that exists in the situation rather than in the design.

32. **A BUCKET EXPIRES MORE QUIETLY THAN A STATEMENT, BECAUSE A SEVERITY LABEL LOOKS LIKE A PROPERTY OF THE FINDING RATHER THAN A CLAIM ABOUT A MOMENT.** §2 #21 extended to bucket assignments (21 Aug 2026). A finding's *statement* invites re-reading — it is prose, it makes claims, and a wrong one eventually reads wrong. **A severity is a single word that reads as intrinsic**, as though `BLOCKS-SEND` were something the finding *is* rather than something the register *concluded on a particular day about a particular arrangement of the code*. So nobody re-derives it, and it survives the very work that should have moved it. **THE OPERATIONAL TEST: WHY WAS THIS BUCKETED HERE, AND IS THAT REASON STILL TRUE?** Worked example: F-P45's migration sat in Bucket 1 **because the writer/reader key mismatch blocked F-P39** — and once that mismatch was fixed, the remaining work was a rename that changes no record's meaning and breaks nothing during a ceremony. The bucket had outlived its reason by days while the row looked entirely current. **The severity is not the finding; it is the finding's relationship to everything else, and that relationship changes every time something else lands.**

33. **A CONSTITUTIONAL RULE WHOSE SUBJECT CANNOT BE IDENTIFIED AT THE POINT OF ENFORCEMENT IS PROSE.** Verbatim (operator, 22 Aug 2026), and **filed explicitly against §2 #6.** *AI output is untrusted data* is a rule about **AI output** — so wherever the code cannot tell which bytes are AI's, the rule has no subject there and cannot bind, however firmly it is written and however many pins it has on other lanes. **Measured, not argued (F-P8):** the `mail.send` execute path cannot distinguish model-originated from human-originated content — the renderer merges the model's draft into the human's field before IPC, the gate's SKIP is byte-identical for both, and `correlationId` is contractually barred from governing. **THE CRUCIAL PART: THIS IS A FINDING ABOUT THE RULE, NOT ABOUT THE CODE.** No implementation defect is being reported; the code is doing what it was built to do. What is defective is a constitutional guarantee that names a category the enforcement point cannot see. **The remedy is therefore never "add a check" — it is to make the subject identifiable, or to restate the rule in terms the enforcement point CAN identify.** For F-P8 the second was chosen: enforce what a *consumer* requires, for **all** sends, regardless of origin. **AND ORIGIN MAY NOT BE RECOVERABLE EVEN IN PRINCIPLE: ORIGIN IS NOT A BINARY PROPERTY OF THE CONTENT AFTER THE USER HAS TOUCHED IT** (operator) — a partially-edited AI draft is neither AI's nor the human's, so even a main-resolved marker could honestly say only *"a draft was generated in this session"*, which is a fact about the session and not about the bytes being sent. **This belongs beside the enforcement audit's PINNED / SCRIPT / PROSE column, because it is the mechanism by which a rule silently moves from PINNED to PROSE without anyone editing it.**
