## What was completed today

### 1. A real product defect — found, diagnosed, fixed, and proven fixed

**F-11b — `TimelineService.flush()` was not a write barrier.**

```ts
if (this.writing || this.pending.length === 0) return;   // the defect
```

A caller that awaited `flush()` while a disk write was already in flight got an
immediately-resolved promise and a false assurance. Two callers depend on that
promise:

- `export()` awaits it and then reads the file → could return rows that
  disagree with `query()` for the same tenant
- `dispose()` awaits it and then stops → **could drop the tail of the activity
  log at shutdown**

The second is data loss, not a test problem.

**How it was caught:** a tenancy test failed intermittently. It was initially
recorded as "did not reproduce" — wrongly. It reproduced on the next full run.
It reproduced **0 times out of 20 in isolation**, because the race only opens
when the machine is under load.

**How it was proven:** a regression test that puts a write in flight
deliberately, so the barrier is either honoured or it is not. Negative control
run against the original code: both cases fail. Against the fix: both pass.
Fix ships as `round22.patch`.

**Consequence recorded:** the retention suite was green *for the wrong reason*
on every prior run — it passed whenever the disk write happened to land in
time. Gate G11 may not be recorded against any run predating this fix.

## Blockers to launch, by tier

Nobody has decided what "launch" means for NeuroPause. That decision is itself
a blocker. Below is what each plausible definition would require.

### Tier 0 — the founder can test it *(reached today, with caveats)*

- ✅ Application runs, signs in, reaches the interface
- ✅ `v1.0.0-rc.16` tagged; its source is **byte-identical** to the certified
  tree apart from the version string (verified)
- 🟡 Windows installer build was still running at the end of the day
- ❌ **macOS release build failed** — and that pipeline has run twice, ever
- ❌ The API stops when a laptop sleeps

### Tier 1 — the three of you use it daily

Everything above, plus:

- **A real server.** Any provider. The deploy scripts are written and
  provider-agnostic — one command once a host exists.
- **One external uptime check on `/health`.** Currently the outage detection
  mechanism is a founder failing to sign in. That is how the last outage ran
  for two weeks.
- **A backup schedule proven by an actual restore.** You already know what an
  unproven backup is worth: six valid archives of an empty database.
- G4, G16 — the app running on real Windows and macOS hardware

### Tier 2 — a first pilot organisation

Everything above, plus:

- **G10–G13** — the tenancy gates. This is a multi-tenant product handling
  medical-device batch and lot traceability. Until eviction, background jobs
  and queue identity are proven per-tenant, one organisation's data can affect
  another's, and nobody would be able to say otherwise.
- **G14, G15** — recovery and restore drills, actually performed
- **G6–G9** — governance verdicts (Saurabh)
- **Managed Postgres with automated backups**, not a container on one box
- **A signed macOS build** — the pipeline currently does not work

### Tier 3 — general availability

Everything above, plus G1, G2, G17, G18, G19, and a resolved answer to O-7:
a repository where a change can be attributed to a person.

## Four decisions nobody has made

These are not engineering tasks. They block work regardless of effort.

1. **What is production for?** A demo, a pilot, or a paying customer? The
   answer changes the substrate, the backup policy and the cost.
2. **Which account owns the infrastructure?** The DigitalOcean account is
   locked and it is not Dishant's. The GitHub repository is on a **personal
   account** (`dishantdobariya91-debug`) — if that account is lost, NeuroPause
   has no source code.
3. **What are the expected governance verdicts?** G6–G9 need them written
   *before* execution. Written afterwards they prove nothing.
4. **Is "local-first" a marketing claim or an architectural constraint?** The
   answer determines whether the backend is optional or required.
